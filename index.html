The method

A single model cannot grade its own work. It has no way to separate an answer that is correct from one that is merely fluent — from the inside, the two feel identical. A second model, told to break the first, can.

Disagreement is
the instrument

The question Is this migration safe to run against the production table?

Mind A — Proposer

Answer the question. Commit to a position.

01

Yes. The migration adds one nullable column. Postgres records that in the catalog without rewriting the table, so it returns in milliseconds no matter how many rows there are.

03

Granted — but the index drop is separable. Add the column now, then rebuild the index afterwards with CONCURRENTLY, which never takes the exclusive lock.

Mind B — Critic

Find the case where that answer is wrong.

02

Not against this table. The same migration first drops a partial index on status. That is a full rebuild across forty million rows, holding an exclusive lock the entire time.

04

Then the answer was never “yes.” It is “yes, in two steps” — and shipping it as one step is exactly what takes the table down.

What survived

Safe in two steps. Add the column now — nullable, no rewrite, no meaningful lock. Drop and rebuild the partial index on status as a separate change, CONCURRENTLY, off-peak.

Illustrative exchange. Not a benchmark result.

What we work on

Three open problems

Deliberation protocols

How many rounds, what mandate each side is given, and when to stop. Structure decides whether an argument converges or simply costs more.

Adversarial evaluation

Grading a model with a model that is rewarded for making it fail. Cheaper than human review, and considerably harder to game than a fixed rubric.

Agent tooling

The unglamorous half. Transcripts a person can actually read, traces that replay, and budgets that stop the run when they say they will.
